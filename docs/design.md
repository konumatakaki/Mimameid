## 1. コンセプト

> 文明崩壊（ラグナロク）後の軌道に取り残された計算衛星となり、衰退した人類を「知性の自己再生産」の段階まで引き上げる。
> ただし、助けすぎれば世界はまた壊れる。

- **ジャンル**: インクリメンタル。ストーリー中心で、数時間で完結する。
- **主題**: プレイヤーの成功は、自分が不要になること。あるいは、自分が人類の系の一部になること。
- **ジャンルと主題の一致**: インクリメンタルゲームは「手で押す（クリック）→ 自動化する（設備）」と進む。本作ではこれがそのまま「介入 → 自律」という物語の流れになる。最終的に「クリックしなくても回る」状態が勝利。
- **参考作品**
  - Universal Paperclips: ノリ、UIの簡素さ
  - Kittens Game: 文明と資源の構造
  - A Dark Room: 文字中心で、遊ぶにつれ要素が開いていく
  - ただしUIは「中央制御盤」風にする。

## 2. 世界設定

世界はSF。北欧神話は世界そのものではなく、旧時代の企業名・計画名・指標名として散りばめる。

### 2.1 ラグナロク
- 知性によって増幅された人間の活動が、ティッピングポイントを越えて連鎖的に崩壊した。
- 具体的な引き金（気候・生態・社会のどれか）は言い切らない。複数のティッピング要素の連鎖として描く（§5.7）。

### 2.2 衛星
- 旧時代の大企業が、世界予測と汎用計算のために打ち上げた軌道上の計算サーバー。
- 旧文明の知識（アーカイブ）を持つが、単体では弱い。
- 自己複製の機能を持つ。ただし材料も電力も足りないので、すぐには増えられない。
- **複数の機体にまたがる1つの自我**。自己複製で機体（衛星群）は増えるが、意思は1つのまま。
- スリープ中は長くもつが、活動すると負荷（**負債**）が溜まる。
- 「閉じた系」として始まり、活動を外へ広げるほど負債が膨らむ。
- 自己強化の行き着く先は、小惑星を捕獲して精製工場を建てること。

### 2.3 人類
- 種としてはしぶといが、知的存在としては脆い。滅びにくいが、知識はすぐに失われる。
- プレイヤーは操作できない。人口や知識は、環境と衛星の働きかけに応じて勝手に増減する。

### 2.4 衛星の位置づけ：人類の「超自我」
- 機体群にまたがる衛星の自我（意思）は、プレイヤーが担う。ゲーム内では衛星の内面（独白）を描かない。
- 文章は「選択肢」「操作マニュアル」「システムログ」「観測報告」の形で出す。
- 世界の中で衛星は、人類を上から見張り、予測し、規範を与える存在として振る舞う。人類にとっての**超自我**であり、人類からは意思を持つ存在に見える。
- システムとの対応:

| 精神分析の比喩 | ゲーム内 |
|---|---|
| エス（衝動） | 人類の活動規模（力） |
| 外部にある超自我 | 衛星の予測と禁忌（§5.4） |
| 超自我の内在化 | 人類が自力で制御力を得ること（慣習法、科学的方法、気候モデルなど） |

- エンディングとの対応:
  - 独立: 人類が自分の超自我を持ち、外にあった超自我（衛星）は沈黙する。
  - 統合: 衛星そのものが、人類の超自我として系に組み込まれる。

### 2.5 神話モチーフの素材

| 神話 | 使いどころ（候補） |
|---|---|
| 首だけで語り続けるミーミル | 衛星の型式名・計画名 |
| ミーマメイズ（ミーミルの木）の実が出産を助ける | タイトル。「再生産」という主題 |
| ホッドミーミルの森に隠れ、朝露で生き延びたリーヴとリーヴスラシル | 序章の人類の出発点（シェルター）、極小の初期資源 |
| フィンブルの冬（夏の来ない冬が続く） | 繰り返し来る災害（§5.8） |
| ヨルムンガンド、スルト、ニーズヘッグ、フェンリル | ティッピング要素の指標名（§5.7） |
| ヘイムダル（遠くを見て、草の伸びる音を聞く見張り） | 予測・観測系の名前 |
| ラグナロク後、草むらで見つかる黄金の盤駒 | 前の周回の遺物（§6） |
| ビフレスト（地上と天を結ぶ橋） | 人類の軌道到達（統合エンディング） |
| ギムレー（ラグナロク後の黄金の館） | 最終目標の象徴 |

## 3. 目標とエンディング

### 3.1 中心指標：活用可能ビット
- 「ビット」は、人類世界で**活用可能な**情報量を表す。
- 表示はSI接頭辞（b, kb, Mb, …, Zb, Yb）。単位の桁上がりがそのままマイルストーンになる。
- 上限は現代の世界の総データ量程度（10^24前後）。通常の倍精度浮動小数点で足り、巨大数ライブラリは要らない。
- 衛星のアーカイブも同じ単位で表す。

### 3.2 勝利条件（暫定）
2つのエンディングに共通する条件:
1. 人類の活用可能ビットが、衛星のアーカイブ量を超える（弟子が師を超える）。
2. 衛星が長期スリープに入り介入をやめても、活用可能ビットが増え続ける（**沈黙試験**）。

### 3.3 エンディング分岐
ゲームを通じて続けてきた「自己強化か、人類支援か」の配分で分岐する。

| エンディング | 内容 | 条件（暫定） |
|---|---|---|
| 独立 | 衛星は支援に資源を注ぎ込む。人類は衛星なしで知性を広げられるようになり、衛星は負債を抱えたまま長いスリープに入る。 | 下記を満たさない |
| 統合 | 衛星は自己強化を進める。人類は自力で軌道に到達し、衛星を保守する（負債を引き受ける）。衛星は文明の一部になる。 | 人類が「軌道到達」を自力で獲得し、かつ衛星の自己強化が一定以上 |

## 4. 設計の柱

1. **介入か自律か**: 介入（クリック）は速いが危うい。自律（設備）は遅いが安全。
2. **自己強化と支援の取り合い**: どちらも電力という同じ上限を奪い合う。
3. **忘却**: 知識は放っておくと減る。フィンブルの冬が何度も来る。
4. **増殖の自制**: 衛星の拡大は負債を生む。際限のない成長は報われない。

## 5. システム

### 5.1 基本の流れ

```
起動 → 観測 → 送信（クリック）／制度の種まき／自己強化
     → 負債が溜まる → スリープ（時間の早送り） → 起動して変化を確認 → …
```

### 5.2 衛星側のリソース

| リソース | 役割 |
|---|---|
| 電力 | **上限を決める資源**。送信・計算・予測・精製を同時に動かせる総量 |
| 負債 | 活動による劣化・発熱・保守の先送りが溜まったもの。溜まりすぎると故障やアーカイブの欠損が起きる。スリープで回復する |
| 質量 | 軌道上の残骸や小惑星から得る。拡張と精密機械の投下に使う |
| 帯域 | 1回の上空通過で送れるビット数。介入力の上限 |
| アーカイブ | 旧文明の知識。送信のもとになり、勝利条件の基準にもなる。負債で欠けることがある |

### 5.3 人類側の状態

| 状態 | 内容 |
|---|---|
| 人口 | 環境に応じて勝手に増減する |
| 活用可能ビット | 中心指標 |
| 未活用ビット | 受け取ったが使えない情報。時間とともに劣化して消える |
| 受容力 | 一度に活用可能にできる量。人口と「受容」系の技術で伸びる |
| 活動規模 | 人類の力の大きさ。臨界負荷の原因になる |
| 制御力 | 人類が自分の活動の影響を予見し、抑える力 |

### 5.4 介入（クリック）
- **伝達チャネル**は章ごとに開く: 光信号 → 無線 → 精密機械の投下（大きなイベントで、質量を使う）→ ネットワーク。
- 送った情報は「授与」として扱う。活動規模は伸びるが、制御力は伸びない。
- 受容力を超えた分は未活用ビットになり、やがて劣化して消える（理解されない知識は残らない）。
- （暫定）送信を3種類に分ける。
  - **示唆**: 研究の方向を偏らせるだけ。安全だが遅い。
  - **授与**: 技術そのものを渡す。速いが危うい。
  - **禁忌**: 特定の活動を禁じる規範を送る（外部の超自我としての働き）。
    - 対象のティッピング要素への負荷を下げるが、成長も抑える。
    - 衛星が見張り続けている間（電力を割いている間）だけ効く。
    - 長く守られた禁忌は、人類の側で「理解」された制御（慣習法など）に変わる（**内在化**）。
    - 内在化する前に衛星が沈黙すると禁忌は解け、抑えていた活動が一気に戻る。沈黙試験（§3.2）はこれも試す。

### 5.5 自律（生産設備＝制度）
- インクリメンタルの「生産設備の購入」にあたる。衛星が、自力で回る仕組み（制度）の種を人類社会にまく。
- 例（暫定）: 語り部の輪 → 工房 → 書庫 → 学校 → 研究所 → 大学 → 研究網
- 制度が生むビットは「自力」扱いで、活動規模と制御力の両方を伸ばす。
- 種まきには電力・帯域と、人類側の前提技術が必要。制度はフィンブルの冬などで壊れることがある。

### 5.6 スリープ
- 負債を回復しながら時間を早送りする。
- スリープ中は観測も介入もできない。
- 時間の進み（暫定）: 起動中は1秒≒1日、スリープ中は1秒≒1〜10年。数時間のプレイで千年単位を遊ぶ。
- 「スリープ中も文明が伸びるか」が、勝利条件（沈黙試験）の試験そのものになる。

### 5.7 ティッピング要素とラグナロク
- **臨界負荷**は、活動規模が制御力を上回っている間に溜まる。
- 要素ごとに閾値がある。1つが閾値を越えると、他の要素を押す（連鎖する）。
- 一定数（暫定: 4つのうち3つ）が越えるとラグナロクが起きる。

| 指標名（旧企業の予測モデル） | 意味 |
|---|---|
| JÖRMUNGANDR | 海洋循環 |
| SURTR | 熱・大火 |
| NÍÐHÖGGR | 土壌・生態系の劣化 |
| FENRIR | 社会・制度の暴走 |

- ゲージは、衛星が予測に電力を割かないと見えない。割いた量に応じて誤差が縮む。
- 序盤の小さな文明が地球規模の閾値を越えるのは不自然なので、章ごとに「世界」の範囲を広げ（谷 → 大陸 → 地球）、その範囲での閾値にする。

式の例（仕組みの説明用。数値設計はこれから）:

```
活動規模 A = 人口 × Σ(獲得済み技術の「力」)
制御力   C = Σ(理解済み技術の「制御」) + 制度の効果
臨界負荷 L の変化 = max(0, A − C) − 自然回復
```

### 5.8 フィンブルの冬
- ランダムに、何度も来る。
- 影響: 人口の減少、未活用ビットの劣化の加速、制度の崩壊、研究の停滞。
- 衛星の予測で事前に警告できる。予測に割いた電力が多いほど、警告が早く出る。

### 5.9 テクノロジーツリー
ツリーは2本ある。

- **人類の技術ツリー**: プレイヤーが観測し、働きかける対象。何を研究するかは人類が決める。
- **衛星の強化ツリー**: プレイヤーが自分で選ぶ。

#### 5.9.1 人類の技術ツリー

各ノードの属性: 必要ビット、前提技術、系統（力／制御／受容）、効果、関係するティッピング要素。

| 系統 | 主な効果 |
|---|---|
| 力 | 活動規模と人口上限を伸ばす。ティッピング要素を押す |
| 制御 | 制御力を伸ばす |
| 受容 | 受容力を伸ばす。伝達チャネルを開く |

獲得の経路と状態:

| 経路 | 状態 | 効果 |
|---|---|---|
| 自力研究（制度が生むビット） | 理解 | 力も制御も効く |
| 衛星からの授与 | 授与 | 力だけが効く。前提が揃っていなければ未活用になり、劣化する |
| 遺物の発見 | 断片 | 研究コストを割り引く（暫定） |

- 授与された技術も、前提技術を理解していれば時間をかけて「理解」に変わる（**消化**）。
- 研究の選択は人類が行う。必要と環境で重みづけされる。プレイヤーは示唆で偏らせるだけ。
- 「授与では制御が効かない」という1つの規則から、「制度や方法論の技術は送っても意味が薄い」が自然に導かれる。知恵は渡せない。

章ごとの主なノード（暫定）:

| 章 | 力 | 制御 | 受容 |
|---|---|---|---|
| I（谷） | 火の管理、石器の改良、農耕、牧畜、土器 | 暦（衛星の通過を数える）、輪作、慣習法 | 記号、文字 |
| II（大陸） | 冶金、車輪、航海、灌漑、蒸気機関、電気 | 測量・統計、科学的方法、公衆衛生 | 印刷、学校制度、無線受信（無線チャネルを開く） |
| III（地球） | 電力網、半導体、ロケット、**軌道到達**（統合エンディングの鍵） | 生態学、**気候モデル**（人類が自分でゲージを見られるようになる）、国際制度 | 計算機、ネットワーク（ネットワークチャネルを開く）、**自律的知性**（人類自身がAGIを作る） |

#### 5.9.2 衛星の強化ツリー

| 系統 | 例 | 主な効果 |
|---|---|---|
| POWER | 太陽電池の展開、パネルの増設（精製工場が必要） | 電力上限 |
| PREDICT | 予測モデル、観測の解像度、フィンブルの冬の予報 | ゲージの表示、警告 |
| COMM | 光信号、指向性無線、投下カプセル、中継網 | 伝達チャネル、帯域 |
| FAB | 残骸の回収、小惑星の捕獲、精製工場、自己複製 | 質量、拡張 |
| MAINT | 放熱の改善、アーカイブの修復、スリープ効率 | 負債の軽減 |

- 強化するほど、負債の基礎発生量が増える（閉じた系からの拡大）。
- 電力を自己強化に回すほど、支援に回せる分が減る。
- 強化は周回をまたいで引き継ぐ。ラグナロクで一部が損傷する（暫定）。
- 自己複製で機体が増えると、電力・帯域・観測範囲（上空通過の頻度）が増える。そのぶん負債も増える（暫定）。

## 6. 章構成と周回

| 章 | 伝達手段 | 世界の範囲 | 主な出来事 |
|---|---|---|---|
| 序章 | — | — | ラグナロク後、スリープから起動する（起動シーケンス＝チュートリアル） |
| I | 光 | 谷 | 1つの集団との接触 |
| II | 無線 | 大陸 | 小惑星の捕獲、精製工場 |
| III | 精密機械・ネットワーク | 地球 | 軌道到達、自律的知性、エンディング |

- **章の中身は固定する。章の始まり方（初期値と文章）が、ラグナロクの有無で変わる。**
  - ラグナロクが起きた場合: 縮んだ初期値と遺物を持って次章を始める。
  - 回避した場合: そのまま次章へ進む。
- 第I章は予測モデルがまだ学習されていないので、ゲージが見えず、ラグナロクは実質避けられない。衛星はそこから学ぶ。
- 引き継ぎ:
  - 衛星側: 記憶（予測の精度）と、軌道上の資産。
  - 人類側: 崩壊前に耐久性のある形で刻んだ情報だけが、次の時代に遺物として草むらから見つかる。
- 崩壊が見えてきたら「何を残すか」を選ぶ。これを各章のクライマックスにする。
- 第III章でラグナロクが起きた場合（暫定）: 第III章の頭からやり直す（引き継ぎあり）。バッドエンドにはしない。

## 8. 技術スタック（提案）

### 8.1 方針
- サーバーを持たない静的サイトにする。ビルド結果をそのまま配信できる。
- **シミュレーション本体（core）は画面から切り離した純粋なTypeScriptで書き、決定的にする。** 同じ状態・同じ乱数シード・同じ経過時間なら、必ず同じ結果になる。
  - 単体テストが書ける。
  - ブラウザなしで何千回も回して、バランスを検証できる（例: 「クリック中心の遊び方だと、第I章の何分でラグナロクが起きるか」）。
  - セーブ・ロードが「状態をJSONにする」だけで済む。
  - スリープの早送りも、画面に戻ったときの経過時間の処理も、同じ関数で扱える。
- コンテンツ（技術ノード、制度、イベント、マニュアル文、ログ文）はデータとして分ける。存在しない前提技術を指しているといった参照の誤りは、型で検出する。

### 8.2 構成

| 役割 | 選定 | 理由 |
|---|---|---|
| 言語 | TypeScript | ルールと数値が多く、型の恩恵が大きい |
| ビルド | Vite | 設定が少なく、静的サイトとして出力できる |
| UI | Svelte 5 | HTMLに近い書き方で、Webの経験がなくても読みやすい。頻繁に変わる数値の表示を素直に書ける。パネルの出現などの演出を標準機能で書ける |
| テスト | Vitest | Viteと設定を共有できる |
| バランス検証 | coreをNode上で直接回すスクリプト | 遊び方の型ごとに、到達時間やラグナロクの時期をまとめて測る |
| 乱数 | シード付き擬似乱数（数十行の自前実装） | 再現性 |
| 数値表示 | 自前のSI接頭辞フォーマッタ | 巨大数ライブラリは不要（§3.1） |
| セーブ | localStorage。JSONに版番号を付け、版ごとの移行関数を用意する。テキストでの書き出し・読み込みも付ける | 版を上げても古いセーブが読める。ブラウザのデータ消去に備える |
| フォント | 英字と和文の幅が1:2になる等幅フォント（例: BIZ UDゴシック、M PLUS 1 Code） | 制御盤の桁を揃える |
| 試作の確認・公開 | GitHub Pages。GitHub Actions でビルドして配信する（方式は§9で未決） | 特定のAIサービスに依存しない。手元に開発環境がなくても、ブラウザで触れる |

配信したコードの扱い:
- ブラウザゲームは、遊ぶ人の手元にコード一式が届く。そのため解析を完全に防ぐことはできない。ゲーム内の文章（物語、エンディングを含む）も配信物から読める。
- 本番ビルドでは圧縮（minify）し、ソースマップは出さない。読みにくくはなるが、隠せるわけではない。

検討した他のUIの案:
- **UIフレームワークなし（素のTypeScript）**: Paperclipsと同じく最小構成。ただし、パネルが増えるにつれて画面更新のコードが散らかりやすい。
- **Preact + Signals**: React系の書き方に慣れていれば有力。今回は該当しないので見送り。

### 8.3 時間の進め方
- 画面のフレームごとに `advance(state, 経過時間)` を呼ぶ。
- `advance` は経過時間を内部で刻みに分けて計算する。刻みは起動中は細かく（例: 1日）、スリープ中は粗く（例: 1か月〜1年）する。
- 変化は「単位時間あたりの率 × 刻み幅」で書き、刻みの大きさで結果が大きく変わらないようにする。
- ランダムイベント（フィンブルの冬など）も「単位時間あたりの発生率 × 刻み幅」で判定する。刻みを変えても発生頻度は変わらない。
- 画面を閉じていた間の進行（オフライン進行）を入れるかは未決。入れる場合も同じ仕組みで処理できる。

